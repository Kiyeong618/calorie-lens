# CalorieLens 功能与数据可视化说明

> 适用版本：CalorieLens 5.3 实验分支（`codex/calorielens`）  
> 项目性质：大学“数据可视化”课程作业 / 个人饮食能量可视化系统  
> 文档更新时间：2026 年 9 月 17 日

## 1. 项目概述

CalorieLens 将“记录一餐”转化为一条完整的数据链：用户输入食物与克重，系统计算热量和三大营养素，按餐次和日期汇总，再通过首页 3D 叙事及趋势页中的统计图形展示饮食结构、进食节律和目标偏差。

项目的重点不是给出医疗诊断，而是帮助用户回答以下问题：

1. 今天摄入了多少能量，还剩多少能量预算？
2. 热量在一天中如何逐餐累积？
3. 用户通常在什么时间进食，每餐规模如何？
4. 蛋白质、碳水和脂肪是否接近个人目标？
5. 哪些食物贡献了最多热量？
6. 最近 7 天和 30 天的摄入是否稳定？
7. 偏离目标主要发生在哪一天、哪一餐或哪一种营养素？

## 2. 项目已经实现的功能

### 2.1 首页：3D 滚动叙事

首页使用 Three.js 和 React Three Fiber 渲染单一 3D 对象，并由滚动进度控制四种连续视觉状态：

- 液态铬表面；
- 结构线框；
- 粒子拆解与重新聚合；
- 蓝黑色透明玻璃体。

四个状态共用同一个高细分二十面体几何拓扑，通过 Shader uniform 改变顶点形态、散射距离、透明度与材质表现。首页同时展示今日热量、目标值、剩余或超出值、餐次数量、三大营养素供能比例、七日均值和三十日稳定性。

当前 3D 对象的尺寸会根据“今日摄入 ÷ 每日目标”小幅变化；形态阶段主要由滚动位置决定。因此它属于数据辅助的艺术叙事，不是精确统计图。精确比较应以趋势页为准。

### 2.2 饮食记录

系统提供三种记录入口：

- 手动记录：搜索本地食物库，输入每种食物的实际克重；
- 图片识别：上传 JPG、PNG 或 WEBP 餐食图片，获得可编辑的识别结果；
- 快速复用：复制最近吃过的餐食或保存的常用餐食模板。

记录过程中可以：

- 选择早餐、午餐、晚餐或加餐；
- 同时添加多种食物；
- 修改食物名称、克重和营养值；
- 新建自定义食物或包装食品；
- 收藏食物并保留最近使用记录；
- 保存、编辑和删除餐次；
- 选择历史日期和具体进食时间。

克重变化会立即触发热量、蛋白质、碳水和脂肪的重新计算。

### 2.3 图片识别

图片识别页包含：

- 图片格式和 10 MB 大小校验；
- 上传预览、识别进度和食物检测框；
- 食物名称、份量及营养值校正；
- 三大营养素供能环图；
- 识别结果保存为正式餐次。

如果配置了 `VITE_AI_ENDPOINT`，系统会调用真实识别接口；如果未配置或接口失败，则自动使用可编辑的演示识别结果，以保证课堂演示完整。因此默认部署不能被描述为真正的在线 AI 识别服务。

### 2.4 身体与目标计算

身体页允许输入：

- 生理性别；
- 年龄；
- 身高；
- 体重；
- 活动水平；
- 减脂、维持或增肌目标。

系统据此计算 BMI、基础代谢 BMR、总日常能量消耗 TDEE 和每日目标热量，并用阶段式能量结构展示“身体尺度 → 静息代谢 → 活动消耗 → 每日目标”。保存后，趋势页的目标线、目标带、偏差和一致性都会同步更新。

### 2.5 趋势分析

趋势页是项目的核心分析页面。用户可以点击日期切换观测日，相关图形会共同读取新的 `selectedDate` 并重新计算。分析窗口主要包括：

- 当前选择日；
- 截至选择日的最近 7 天；
- 数据中的最近 30 天。

系统还会基于记录自动生成简短观察，例如目标达成情况、营养素偏差和进食时间变化。

### 2.6 本地持久化

用户档案、目标、餐食记录、自定义食物、收藏、最近食物和餐食模板均保存在浏览器 `localStorage` 中。数据在同一浏览器刷新后仍然存在，但不会自动同步到其他设备，也不等同于云端数据库。

当前正式版与 `/terrain/` 实验版位于同一个 GitHub Pages 域名下，浏览器存储按“域名”而不是路径隔离，因此两者会共享本地数据。

## 3. 项目对哪些数据进行了可视化

| 数据层级 | 原始或派生字段 | 可视化用途 |
| --- | --- | --- |
| 用户档案 | 性别、年龄、身高、体重、活动水平、目标 | BMI、BMR、TDEE、每日目标与目标区间 |
| 食物 | 名称、克重、每 100 克热量、蛋白质、碳水、脂肪 | 食物密度散点、热量贡献矩形树图 |
| 餐次 | 类型、时间、包含的食物、餐次营养合计 | 累计摄入、24 小时节律、餐次堆叠、箱线图 |
| 每日记录 | 总热量、三大营养素、目标值 | 今日预算、目标带、偏差图、营养热图 |
| 时间窗口 | 最近 7 天、最近 30 天 | 周趋势、月度稳定性、历史范围与异常检测 |

## 4. 趋势页可视化模块说明

### 4.1 今日能量预算条（Calorie Budget Strip）

**回答的问题：** 今天已经摄入多少，还能摄入多少？

- 条形长度：当日总摄入热量；
- 目标标记：个人每日目标热量；
- 状态颜色：接近、低于或超过目标；
- 辅助公式：`剩余热量 = 每日目标 − 今日摄入`。

### 4.2 一日累计摄入图（Cumulative Intake）

**回答的问题：** 热量在一天中是怎样逐餐增加的？

- X 轴：餐次发生时间；
- Y 轴：累计摄入千卡；
- 节点：每一餐保存后的累计值；
- 参考线：每日目标。

系统先按时间排序餐次，再依次累加餐次热量。因此修改餐次时间或热量后，折线形态会同步变化。

### 4.3 24 小时饮食节律图（Meal Rhythm Polar）

**回答的问题：** 用户吃得早还是晚，每餐规模多大？

- 环形角度：一天中的进食时间；
- 圆点面积：该餐热量；
- 圆点颜色：早餐、午餐、晚餐或加餐；
- 背景范围：最近 7 天的个人进食时间分布；
- 文字指标：首餐、末餐和进食窗口时长。

### 4.4 三大营养素目标轨（Macro Bullet）

**回答的问题：** 当天的蛋白质、碳水和脂肪与目标相比处于什么位置？

每种营养素使用一条 Bullet Chart：

- 实心条：选择日的实际克数；
- 范围带：最近 7 天的最小值至最大值；
- 目标刻度：根据个人目标计算出的建议克数。

### 4.5 三大营养素供能条（Macro Energy Composition）

**回答的问题：** 当天的能量主要由哪种宏量营养素提供？

系统先把克数换算为能量：

```text
蛋白质供能 = 蛋白质克数 × 4
碳水供能   = 碳水克数 × 4
脂肪供能   = 脂肪克数 × 9
```

每段宽度表示该营养素在三者总供能中的比例，而不是简单比较克数。

### 4.6 食物密度散点图（Food Galaxy）

**回答的问题：** 哪些食物高热量、哪些食物高蛋白？

- X 轴：每 100 克热量；
- Y 轴：每 100 克蛋白质；
- 圆面积：实际摄入克重；
- 每个圆点：一种实际记录的食物。

当前趋势页传入的是选择日的数据，因此显示的是该日食物，而不是 30 天累计数据。

### 4.7 食物热量贡献矩形树图（Food Contribution Treemap）

**回答的问题：** 当天热量主要来自哪些食物？

- 每个矩形：一种食物；
- 矩形面积：该食物贡献的实际热量；
- 标签：食物名称、千卡及占当天热量的比例。

同名食物会先合并，再按热量从高到低排列。

### 4.8 七日目标带（Weekly Target Band）

**回答的问题：** 最近一周哪几天偏离目标？

- X 轴：日期；
- 折线：每天实际摄入；
- 中心目标线：个人每日目标；
- 阴影带：目标值的 ±10%；
- 可点击数据点：切换趋势页的选择日期。

### 4.9 七日餐次堆叠图（Weekly Meal Stack）

**回答的问题：** 某天偏高主要由哪一餐造成？

- 每根柱：一天；
- 柱体总高度：当天总热量；
- 堆叠片段：早餐、午餐、晚餐和加餐的热量；
- 参考线：每日目标。

### 4.10 三十日目标偏差图（Monthly Deviation）

**回答的问题：** 一个月内的稳定期和异常日在哪里？

- X 轴：日期；
- Y 值：`实际摄入 − 每日目标`；
- 零线：刚好达到目标；
- 正值：高于目标；
- 负值：低于目标；
- ±10% 区间：项目定义的稳定范围。

页面同时统计平均偏差、目标范围内天数、最大超出、最大不足和当前连续稳定天数。

### 4.11 一周营养热图（Macro Heatmap）

**回答的问题：** 哪一天、哪种营养素偏离目标最明显？

- 列：最近 7 天；
- 行：蛋白质、碳水、脂肪；
- 色深：`实际克数 ÷ 目标克数`；
- 单元格提示：实际值、目标值和完成比例。

### 4.12 餐次热量箱线图（Meal Distribution Box Plot）

**回答的问题：** 最近 30 天哪类餐次最容易吃多或波动最大？

系统分别收集早餐、午餐、晚餐和加餐的热量，计算：

- 最小值；
- 第一四分位数 Q1；
- 中位数；
- 第三四分位数 Q3；
- 最大值。

箱体用于观察典型范围，中位线表示常见水平，两端表示历史极值。

## 5. 核心计算公式

### 5.1 食物与餐次

```text
食物热量 = 每 100 克热量 × 实际克重 ÷ 100
食物蛋白质 = 每 100 克蛋白质 × 实际克重 ÷ 100
食物碳水 = 每 100 克碳水 × 实际克重 ÷ 100
食物脂肪 = 每 100 克脂肪 × 实际克重 ÷ 100

一餐营养 = 该餐全部食物营养之和
一天营养 = 当天全部餐次营养之和
```

### 5.2 身体与目标

```text
BMI = 体重(kg) ÷ 身高(m)²

BMR（男性）= 10W + 6.25H − 5A + 5
BMR（女性）= 10W + 6.25H − 5A − 161

TDEE = BMR × 活动系数

减脂目标 = TDEE × 0.85
维持目标 = TDEE × 1.00
增肌目标 = TDEE × 1.10
```

其中 W 为体重（kg），H 为身高（cm），A 为年龄。

### 5.3 偏差与一致性

```text
剩余热量 = 每日目标 − 实际摄入
热量偏差 = 实际摄入 − 每日目标
一致性 = max(0, 1 − |实际摄入 − 目标| ÷ 目标) × 100
```

“一致性”是本课程项目为观察目标接近度定义的展示指标，不是医学指标。

## 6. 数据如何从输入流向图表

```text
手动输入 / 图片识别 / 最近餐食
                ↓
FoodItem：名称、克重、每 100 克营养
                ↓
按克重重新计算实际营养值
                ↓
Meal：餐次类型、时间、食物列表、餐次合计
                ↓
DailyRecord：日期、全天总热量、蛋白质、碳水、脂肪
                ↓
localStorage 持久化
                ↓
useAppData 监听 calorielens:update / storage 事件
                ↓
selectors 生成日、周、月统计数据
                ↓
首页 3D 叙事 + 趋势页 SVG / HTML 图形
```

图表组件不直接负责业务汇总。日期筛选、营养换算、周/月截取、四分位数、偏差和洞察等逻辑集中在 `src/data/selectors.ts`，这样可以避免同一指标在不同图表中使用不同算法。

## 7. 数据是否可以调整

可以。以下操作都会影响可视化结果：

| 用户操作 | 会发生的变化 |
| --- | --- |
| 修改食物克重 | 该食物、该餐、当天和相关周/月图表重新计算 |
| 新增或删除食物 | Treemap、散点、宏量营养和总热量变化 |
| 修改餐次类型 | 餐次堆叠图和箱线图中的分组变化 |
| 修改进食时间 | 累计摄入图和 24 小时节律图变化 |
| 新增或删除餐次 | 当天总量、周趋势和月度偏差变化 |
| 修改身体档案 | 目标热量、目标线、目标带和一致性变化 |
| 选择不同日期 | 当日相关图形联动更新 |

## 8. 演示数据与真实输入数据

项目首次运行时会生成 30 天演示数据，用于保证趋势页立即具有可观察的时间序列。演示数据包含稳定期、偏高日、晚餐逐渐推迟和重新接近目标等叙事情节，而不是完全随机生成。

用户新增的记录会写入同一个数据集合。因此在没有清理演示数据的情况下，趋势页展示的是“演示历史数据 + 用户新记录”。项目会保留含个人来源的记录，不会在普通版本迁移时直接覆盖它们。

如需进行严格的真实用户测试，建议增加以下能力：

1. “清空演示数据并开始个人记录”按钮；
2. 演示模式与个人模式的显式切换；
3. 正式版与实验版不同的存储前缀；
4. JSON / CSV 导入导出；
5. 云端账户同步或数据库存储。

## 9. 技术实现概览

| 层级 | 技术与职责 |
| --- | --- |
| 应用框架 | React 19、TypeScript、Vite |
| 路由 | React Router，组织首页、记录、识别、身体和趋势页面 |
| 3D 首页 | Three.js、React Three Fiber、自定义 GLSL Shader |
| 滚动控制 | GSAP ScrollTrigger，将页面滚动映射为 0–1 进度 |
| 页面动效 | Motion / CSS Transition |
| 统计与比例尺 | D3 scale、项目自定义 selectors |
| 图表渲染 | 以 React SVG / HTML 为主，识别页环图使用 ECharts |
| 图标 | Lucide React |
| 数据存储 | 浏览器 localStorage |
| 部署 | GitHub Actions + GitHub Pages |

主要代码位置：

- `src/data/store.ts`：读取、写入、演示数据和餐次增删改；
- `src/data/selectors.ts`：全部派生数据、统计和洞察；
- `src/utils.ts`：BMI、BMR、TDEE、目标及克重换算；
- `src/pages/Trends.tsx`：趋势页模块组织与日期联动；
- `src/components/visualizations/ObservationVisuals.tsx`：趋势页主要图形；
- `src/components/visualizations/AnalyticVisuals.tsx`：食物密度等分析图形；
- `src/components/three/ChromeSphere.tsx`：实验版首页 3D 对象和状态切换；
- `src/components/three/ChromeSphereShader.ts`：顶点变形、铬、线框、粒子和玻璃材质；
- `src/services/FoodRecognitionService.ts`：真实识别接口与演示回退。

## 10. 课程展示建议

建议按照“输入 → 计算 → 表达 → 洞察”的顺序演示：

1. 在身体页修改体重、活动水平或目标，展示每日目标如何变化；
2. 在记录页添加一餐，改变食物克重，说明每 100 克数据如何换算为实际摄入；
3. 回到首页展示今日总量、营养比例和 3D 叙事的变化；
4. 进入趋势页，用预算条说明当天状态；
5. 用累计摄入和 24 小时节律说明“什么时候吃”；
6. 用散点图和 Treemap 说明“吃了什么”；
7. 用七日目标带和餐次堆叠说明“哪天、哪一餐造成偏差”；
8. 用月度偏差、热图和箱线图总结长期规律；
9. 最后说明演示数据、localStorage 和非医疗用途等边界。

## 11. 项目边界

- 本项目提供的是课程展示级营养估算，不构成医疗或专业营养建议；
- 食物营养值来自项目内置数据库或用户输入，精度受数据来源和份量估计影响；
- 默认图片识别可能是演示回退，并非真实 AI 推理；
- 数据只保存在本地浏览器，没有账户、云同步和多人协作；
- 3D 首页强调艺术表达，不应用于精确读取数值；趋势页才承担分析任务。
